## 1. Missing Data संभालब (Imputation)

### विचार
असल dataset मे लगभग हरदम छेद रहैत अछि — एकटा sensor जे reading log नहि कऽ सकल, एकटा customer जे optional form field छोड़ि देलक, एकटा survey response खाली छोड़ल गेल। **Imputation** ई छेदके समझदारीसँ भरबाक अभ्यास थिक (केवल कोनो incomplete चीज हटेबाक बदला), कियाक एकल missing value वला हर row फेकि देब बहुत रास अन्यथा-नीक डेटा बर्बाद कऽ सकैत अछि।

### जुड़ल उदाहरण
कल्पना करू एकटा class attendance register जाहिमे किछु विद्यार्थी एकटा quiz क marks लिखय बिसरि गेलैथ। अहाँ केवल एकटा missing quiz score क कारणे *पूरा* विद्यार्थीक record नहि फेकब — अहाँ ओहिमे class average भरि सकैत छी ओहि quiz लेल, या ओहि विद्यार्थीक दोसर quiz क औसत, या बस "absent" mark कऽ सकैत छी जँ ई सार्थक हो। कोन approach ठीक अछि से एहिपर निर्भर करैत अछि जे डेटा *किएक* missing अछि — आ ई निर्णय असल कौशल थिक, केवल एकटा formula चुनब नहि।

### ML मे ई कतए भेटत
- लगभग हर असल dataset (customer records, sensor logs, medical data, surveys) मॉडल तक पहुँचबासँ पहिने missing values रखैत अछि।
- गलत imputation strategy चुनला पर चुपचाप bias भरि सकैत अछि — जेना, missing income केँ overall average सँ भरब कम-आयवला customer केँ अधिक अमीर देखा सकैत अछि, predictions केँ तिरछा कऽ।

### अभ्यास
1. **हाथसँ (concept):** एकटा house listing dataset क `garage_size` column 30% rows मे missing अछि। एकर दूटा अलग-अलग कारण की भऽ सकैत अछि — आ की भरबाक "सही" तरीका कारणक अनुसार अलग होएत? (संकेत: "missing कियाक घरमे असलमे garage नहि अछि" बनाम "missing कियाक गलतीसँ field नहि भरल गेल" — दुनू लेल बहुत अलग fix चाही।)
2. **Pandas — जाँचू आ impute करू:**
   ```python
   import pandas as pd
   import numpy as np

   df = pd.DataFrame({
       "age": [25, np.nan, 35, 40, np.nan, 22],
       "income": [50000, 60000, np.nan, 80000, 45000, np.nan],
       "city": ["Patna", "Delhi", "Patna", np.nan, "Mumbai", "Delhi"]
   })

   print(df.isnull().sum())  # how many missing per column

   # Fill numeric columns with the median (robust to outliers)
   df["age"] = df["age"].fillna(df["age"].median())
   df["income"] = df["income"].fillna(df["income"].median())

   # Fill categorical column with the most frequent value (mode)
   df["city"] = df["city"].fillna(df["city"].mode()[0])

   print(df)
   ```
3. **scikit-learn — एहि काजक मानक औजार:**
   ```python
   from sklearn.impute import SimpleImputer
   import pandas as pd
   import numpy as np

   df = pd.DataFrame({"age": [25, np.nan, 35, 40, np.nan, 22]})
   imputer = SimpleImputer(strategy="mean")   # try "median", "most_frequent" too
   df["age_imputed"] = imputer.fit_transform(df[["age"]])
   print(df)
   ```
4. **सोचू:** Extreme outliers वला column लेल missing value केँ **mean** सँ भरब किएक खराब विकल्प भऽ सकैत अछि, आ **median** एकटा सुरक्षित default किएक थिक? (विषय 1.3 क outliers averages केँ कोना बिगाड़ैत अछि ओहि चर्चा सँ जुड़ल।)

## 2. Categorical Variables क Encoding

### विचार
मॉडल गणित करैत अछि — हुनका text label चाही नहि, जेना "Delhi" या "Small/Medium/Large," बल्कि संख्या चाही। **Encoding** categorical (text/label) columns केँ numeric रूपमे बदलैत अछि ताकि मॉडल इनका उपयोग कऽ सकय। अलग-अलग स्थितिक लेल अलग encoding style फिट बैसैत अछि:
- **One-hot encoding**: हर category लेल एकटा अलग 0/1 column बनाउ (जेना `is_Delhi`, `is_Mumbai`, `is_Patna`)। जकर categories मे *कोनो* स्वाभाविक क्रम नहि अछि हुनका लेल सबसँ नीक।
- **Label encoding**: हर category केँ एकटा integer दिय (Delhi=0, Mumbai=1, Patna=2)। सरल, मुदा एकटा गलत क्रम बताबैत अछि जँ तक categories असलमे *क्रमबद्ध* नहि होइथ।
- **Ordinal encoding**: label encoding जकाँ, मुदा जानबूझकऽ उपयोग होइत अछि जखन असलमे एकटा क्रम *होइत* अछि (Small=0, Medium=1, Large=2)।
- **Target encoding**: हर category केँ target variable सँ निकालल एकटा संख्या सँ बदलू (जेना city नाम केँ ओहि city क औसत purchase amount सँ बदलू)। शक्तिशाली मुदा असावधानीसँ कएला पर target information leak करबाक जोखिम अछि।

### जुड़ल उदाहरण
कल्पना करू डाक केँ bins मे छाँटब। One-hot encoding एहन थिक जेना हर city केँ अपन *अलग bin* देब — एकटा चिट्ठी या त "Delhi" bin (1) मे जाइत अछि या नहि (0), कोनो city दोसरसँ "अधिक" नहि थिक। Label/ordinal encoding एहन थिक जेना हर चिट्ठी पर priority क आधार पर संख्या लिखब — ठीक अछि जखन असल ranking अछि (जेना shirt sizes S/M/L), मुदा भ्रामक जँ अहाँ cities केँ 0, 1, 2 numbered करी जेना Mumbai किछु तरहेँ Delhi सँ "बेसी" होइक केवल एहि लेल जे ओकरा बड़का संख्या भेटल।

### ML मे ई कतए भेटत
- लगभग हर असल dataset मे categorical columns रहैत अछि (city, product category, job title, education level) — इनका encode कएने बिना अहाँ इनका अधिकांश ML algorithms मे सीधे नहि दऽ सकैत छी।
- गलत encoding चुनब एकटा क्लासिक शुरुआती गलती थिक: असलमे unordered category (जेना city नाम) केँ label-encode करब मॉडलके एकटा नकली numeric संबंध सिखा सकैत अछि जे असलमे नहि अछि ("Mumbai (2), Delhi (1) क दुगुना" क कोनो मतलब नहि अछि)।

### अभ्यास
1. **हाथसँ (concept):** `shirt_size` column लेल Small/Medium/Large values सहित, आ `favorite_color` column लेल Red/Blue/Green values सहित, कोन encoding (one-hot बनाम ordinal) हर column लेल बेसी फिट बैसैत अछि, आ किएक?
2. **Pandas/scikit-learn — one-hot encoding:**
   ```python
   import pandas as pd

   df = pd.DataFrame({"city": ["Delhi", "Mumbai", "Patna", "Delhi", "Mumbai"]})
   one_hot = pd.get_dummies(df["city"], prefix="city")
   print(one_hot)
   ```
3. **scikit-learn — label/ordinal encoding:**
   ```python
   from sklearn.preprocessing import OrdinalEncoder

   df = pd.DataFrame({"shirt_size": ["Small", "Large", "Medium", "Small", "Large"]})
   encoder = OrdinalEncoder(categories=[["Small", "Medium", "Large"]])  # explicit order matters!
   df["size_encoded"] = encoder.fit_transform(df[["shirt_size"]])
   print(df)
   ```
4. **Target encoding (concept + छोट implementation):**
   ```python
   import pandas as pd

   df = pd.DataFrame({
       "city": ["Delhi", "Mumbai", "Delhi", "Patna", "Mumbai", "Patna"],
       "purchase_amount": [500, 800, 600, 200, 900, 250]
   })

   city_avg = df.groupby("city")["purchase_amount"].mean()
   df["city_target_encoded"] = df["city"].map(city_avg)
   print(df)
   ```
   **सोचू:** Target encoding किएक जोखिम भरल अछि जँ अहाँ अपन *पूरा* dataset (encode कएल जाइत row सहित) उपयोग कऽ averages निकालैत छी, ओहि row केँ बाहर निकालब या केवल training data उपयोग करबाक बदला? (ई "data leakage" क एकटा आम स्रोत थिक — एकटा विषय जे Phase 3 सँ आगाँ बहुत मायने रखत।)

## 3. फीचर स्केलिंग (Standardization & Normalization)

### विचार
कैइयो ML algorithms अहाँक features क *scale* के प्रति संवेदनशील अछि। जँ एकटा column 0-1 (जेना probability) मे अछि आ दोसर 0-500,000 (जेना income) मे अछि, त बड़का-scale वला column गणनामे हावी भऽ सकैत अछि केवल एहि लेल जे ओकर संख्या बड़ अछि — ई एहि लेल नहि जे ई असलमे बेसी जरूरी अछि। **Scaling** सबटा features केँ एकसमान आधार पर आनैत अछि।
- **Standardization** (Z-score scaling): फेरसँ scale करू ताकि हर column क mean 0 आ standard deviation 1 हो। Formula: `(x - mean) / std`।
- **Normalization** (Min-Max scaling): फेरसँ scale करू ताकि हर column क values 0 आ 1 क बीच पड़य। Formula: `(x - min) / (max - min)`।

### जुड़ल उदाहरण
कल्पना करू एकटा talent competition जज करब जतय एक judge 10 मेसँ अंक दैत छथि आ दोसर 1,000 मेसँ। जँ अहाँ बस हुनकर raw scores जोड़ि दी, त दोसर judge क राय पहिल judge क राय केँ पूरा तरहेँ डुबा देत — केवल संख्या range क कारणे, हुनकर निर्णय बेसी मूल्यवान होबाक कारणे नहि। Scaling एहन थिक जेना दुनू judge क score केँ *एकहि* scale पर आनब (मानू, दुनू 100 मेसँ) मिलेबासँ पहिने, ताकि हर judge क राय असलमे अनुपातिक रूपसँ गिनल जाय।

### ML मे ई कतए भेटत
- **Distance-based algorithms** (k-NN, k-means clustering, SVMs) scale सँ सीधा प्रभावित होइत अछि — एकटा unscaled "income" column एकटा unscaled "age" column पर distance गणनामे पूरा तरहेँ हावी भऽ सकैत अछि केवल एहि लेल जे ओकर संख्या हजारों गुना बड़ अछि।
- **Gradient descent** (विषय 1.4) scaled features पर बहुत तेज आ भरोसेमंद ढंगसँ converge करैत अछि — बहुत अलग-अलग range वला unscaled data एकटा लम्बा सँकरा घाटी जकाँ आकारक loss surface बनाबैत अछि (याद अछि "narrow valley" momentum उदाहरण?), जे optimizers लेल ठीक कठिन मामला थिक।
- Tree-based मॉडल (decision trees, random forests, XGBoost) एकटा उल्लेखनीय अपवाद थिक — ई सामान्यतः feature scale क प्रति संवेदनशील *नहि* होइत अछि, कियाक ई threshold पर split करैत अछि, distance गणना नहि करैत अछि।

### अभ्यास
1. **हाथसँ:** Column `[10, 20, 30, 40, 50]` लेल, कम सँ कम दू values लेल standardized version निकालू (mean घटाउ, standard deviation सँ भाग दिय)। फेर एहि दुनू values लेल normalized (min-max) version निकालू।
2. **scikit-learn:**
   ```python
   from sklearn.preprocessing import StandardScaler, MinMaxScaler
   import pandas as pd

   df = pd.DataFrame({
       "age": [22, 25, 47, 35, 46],
       "income": [25000, 32000, 95000, 60000, 52000]
   })

   standard_scaler = StandardScaler()
   df_standardized = pd.DataFrame(standard_scaler.fit_transform(df), columns=df.columns)
   print("Standardized:\n", df_standardized)

   minmax_scaler = MinMaxScaler()
   df_normalized = pd.DataFrame(minmax_scaler.fit_transform(df), columns=df.columns)
   print("\nNormalized:\n", df_normalized)
   ```
3. **सोचू:** Standardize कएलाक बाद, (`.mean()` आ `.std()` सँ) जाँच करू जे हर column क सचमुच mean ≈ 0 आ std ≈ 1 अछि। Normalize कएलाक बाद, जाँच करू जे हर column क min आ max 0 आ 1 अछि।
4. **महत्वपूर्ण चेतावनी:** अहाँके scaler केँ *केवल* training data पर `.fit()` किएक करक चाही, फेर validation/test data पर बस `.transform()` (फेरसँ fit नहि) किएक करक चाही? जँ अहाँ पूरा dataset पर, split करबासँ पहिने scaler fit करी त कोन असल दुनियाक समस्या पैदा होएत?

## 4. फीचर सिलेक्शन (Feature Selection)

### विचार
अहाँक dataset क हर column असलमे उपयोगी नहि होइत अछि — किछु irrelevant noise होइत अछि, किछु redundant (मूल रूपसँ दोसर column जकाँ एकहि बात कहैत) होइत अछि, आ बेसी column होबाक कारणे मॉडल धीमा, बुझब कठिन, आ overfitting (असल pattern सीखबाक बदला noise याद करब — ई औपचारिक रूपसँ Phase 3 मे भेटत) क शिकार भऽ सकैत अछि। **Feature selection** ई तय करबाक प्रक्रिया थिक जे कोन features असलमे मॉडलमे अपन जगह लायक अछि।

### जुड़ल उदाहरण
कल्पना करू अहाँ एकटा गाड़ीक समस्या diagnose कऽ रहल छी आ एकटा mechanic अहाँके पिछला महीनाक हर sensor reading क 50-पन्नाक printout दैत छथि। एहिमेसँ अधिकांश आइक समस्यासँ असंबद्ध अछि। एकटा नीक mechanic जनैत छथि जे लक्षणक लेल कोन 3-4 readings असलमे मायने रखैत अछि, आ बाकी छोड़ि दैत छथि — एहि लेल नहि जे बाकी readings गलत अछि, बल्कि एहि लेल जे ई *एहि* diagnosis लेल insight क बदला noise जोड़ैत अछि।

### ML मे ई कतए भेटत
- **कम, बेसी relevant features** प्रायः एकटा एहन मॉडल बनाबैत अछि जे train करबामे तेज, stakeholder केँ समझाबमे आसान, आ overfit होबाक कम संभावना वाला अछि।
- Feature selection विशेष रूपसँ ओहि domains मे जरूरी अछि जतय rows क संख्याक तुलनामे raw columns क संख्या बहुत बेसी अछि — जेना genomics या किछु sensor/IoT datasets — जतय "बहुत बेसी features, पर्याप्त डेटा नहि" एकटा असल जोखिम अछि।

### अभ्यास
1. **Correlation-आधारित selection (सरल मुदा उपयोगी):**
   ```python
   import pandas as pd
   import numpy as np

   np.random.seed(0)
   df = pd.DataFrame({
       "feature_a": np.random.rand(100),
       "feature_b": np.random.rand(100),
   })
   df["feature_c"] = df["feature_a"] * 2 + np.random.normal(0, 0.01, 100)  # nearly identical to feature_a
   df["target"] = df["feature_a"] * 3 + np.random.normal(0, 0.1, 100)

   print(df.corr()["target"].sort_values(ascending=False))
   ```
   कोन feature `target` सँ सबसँ बेसी correlate करैत अछि? कोन दू features एक-दोसरासँ एतेक मिलैत-जुलैत अछि जे दुनूकेँ राखब शायद redundant होएत?
2. **scikit-learn — मॉडलसँ automatic feature importance:**

## 5. असंतुलित Dataset संभालब (SMOTE, Class Weights)

### विचार
एकटा imbalanced dataset ओ थिक जतय एकटा class दोसरसँ बहुत बेसी अछि — जेना 99% "fraud नहि" आ 1% "fraud" transaction। एहिपर बिना सोचल train कएल मॉडल केवल *हरदम "fraud नहि" predict कऽ* 99% accuracy पा सकैत अछि — तकनीकी रूपसँ सही, मुदा पूरा तरहेँ बेकार, कियाक ई कहियो ओ दुर्लभ मामला नहि पकड़ैत अछि जकर अहाँके असलमे परवाह अछि। दूटा आम fix:
- **Class weights**: मॉडलके बताउ जे training काल minority class पर गलती पर "बेसी ध्यान दिय," ओहि errors केँ बेसी भारी दंड द कऽ।
- **SMOTE** (Synthetic Minority Oversampling Technique): minority class क नव, synthetic उदाहरण बनाउ (मौजूदा minority उदाहरणक बीच interpolated) ताकि मॉडल बेसी balanced training data देखय।

### जुड़ल उदाहरण
कल्पना करू एकटा security guard केँ shoplifter पहचानब सिखा रहल छी, जतय shoplifter 1,000 मे सँ 1 customer अछि। जँ guard बस मानि लेथि "कहियो केओ shoplifter नहि होइत," त ओ raw accuracy सँ 99.9% बेर सही होएता — मुदा ओ बिलकुल शून्य shoplifter पकड़ता, जे guard रखबाक पूरा मकसद केँ हरा देत। एकटा नीक approach ई अछि जे training काल guard केँ जानबूझकऽ shoplifting व्यवहारक *बहुत बेसी उदाहरण* देखाउ (भलेहि staged/synthetic — जेना SMOTE) या स्पष्ट रूपसँ कहू "shoplifter छूटब false alarm सँ बहुत बड़ बात अछि" (जेना class weights) — ताकि ओ असलमे ओहि दुर्लभ, महत्वपूर्ण मामला नोटिस करब सीखय।

### ML मे ई कतए भेटत
- **Fraud detection, disease diagnosis, manufacturing defect detection, churn prediction** — लगभग हर उच्च-मूल्य वला असल-दुनियाक classification समस्या स्वाभाविक रूपसँ imbalanced अछि, कियाक रोचक घटना (fraud, disease, defect, churn) परिभाषानुसार दुर्लभ अछि।
- Imbalanced data पर accuracy एकटा भ्रामक metric बनि जाइत अछि — यैह किएक precision, recall, आ F1-score जकाँ metrics (जे अहाँ Phase 3 मे भेटब) एहि समस्या लेल plain accuracy सँ बहुत बेसी मायने रखैत अछि।

### अभ्यास

## 6. Outlier Detection

### विचार
एकटा outlier एकटा data point थिक जे बाकी dataset सँ नाटकीय रूपसँ अलग अछि — ई एकटा असल दुर्लभ घटना, एकटा data entry गलती, या एकटा sensor glitch भऽ सकैत अछि। **Outlier detection** ई बिंदु खोजबाक बारेमे अछि ताकि अहाँ जानबूझकऽ तय कऽ सकी की करब (राखू, जाँचू, cap करू, या हटाउ) एकरा चुपचाप अपन analysis या मॉडल केँ बिगाड़य देबाक बदला।

### जुड़ल उदाहरण
कल्पना करू एकटा class क test scores जाँचैत छी आ देखैत छी एकटा विद्यार्थी "-5" पेलक आ दोसर "1000" पेलक, 100 मेसँ एकटा test मे। ई केवल "प्रभावशाली खराब" या "प्रभावशाली नीक" नहि थिक — ई लगभग निश्चित रूपसँ data entry गलती थिक जकर जाँच जरूरी अछि, असल performance नहि जकरासँ सीखल जाय। मुदा context मायने रखैत अछि: जँ अहाँ *income* data देखि रहल छी आ एकटा व्यक्ति median सँ 100 गुना कमाइत अछि देखैत छी, त ई एकटा पूरा तरहेँ असल (भलेहि दुर्लभ) उच्च कमेनिहार भऽ सकैत अछि, गलती नहि — एकहि statistical "outlier" label केँ दुनियाक बारेमे असलमे की सत्य अछि ओकर अनुसार बहुत अलग handling चाही।

### ML मे ई कतए भेटत
- Outliers mean जकाँ statistics (विषय 1.3) केँ बहुत बिगाड़ि सकैत अछि आ MSE (विषय 1.2) जकाँ loss functions पर हावी भऽ सकैत अछि, कियाक squared error बड़का deviations केँ असमान रूपसँ दंडित करैत अछि — किछु extreme outliers चुपचाप पूरा मॉडलक training केँ बिगाड़ि सकैत अछि।
- Outlier detection EDA (विषय 2.1) मे एकटा नियमित, आवश्यक step थिक — प्रायः इएठाम अहाँ असल data quality bugs पकड़ैत छी हुनका आगाँ analysis केँ दूषित करबासँ पहिने।

### अभ्यास
1. **IQR method (एकटा क्लासिक, सरल, बुझबामे आसान approach):**
   ```python
   import pandas as pd
   import numpy as np

   data = pd.Series([12, 14, 15, 15, 16, 18, 19, 20, 21, 100])  # 100 looks suspicious

   Q1 = data.quantile(0.25)
   Q3 = data.quantile(0.75)
   IQR = Q3 - Q1
   lower_bound = Q1 - 1.5 * IQR
   upper_bound = Q3 + 1.5 * IQR

   outliers = data[(data < lower_bound) | (data > upper_bound)]
   print("Outliers:", outliers.tolist())
   ```
2. **Boxplot सँ visual detection:**
   ```python
   import seaborn as sns
   import matplotlib.pyplot as plt

   sns.boxplot(x=data)
   plt.title("Boxplot — dots beyond the whiskers are flagged outliers")
   plt.show()
   ```
3. **Z-score method (Section 3 क standardization विचार उपयोग करैत अछि):**
   ```python
   from scipy import stats
   import numpy as np

   z_scores = np.abs(stats.zscore(data))
   outliers_z = data[z_scores > 2]   # commonly 2 or 3 standard deviations away
   print("Outliers (z-score method):", outliers_z.tolist())
   ```
