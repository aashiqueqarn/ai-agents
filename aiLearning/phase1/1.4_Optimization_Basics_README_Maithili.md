## 1. कॉन्वेक्स बनाम नॉन-कॉन्वेक्स फंक्शन (Convex vs Non-Convex Functions)

### विचार
एकटा **convex** function मे बिलकुल एकहि "कटोरा" रहैत अछि — अहाँ कतहुसँ शुरू करी, नीचाँ चलला पर हरदम एकहि सबसँ नीचाँक बिंदु (global minimum) तक पहुँचब। एकटा **non-convex** function मे कैइयो गड्ढा आ उभार रहि सकैत अछि — कटोराक भीतर कटोरा — त अहाँ कतएसँ शुरू करैत छी से तय करत जे अहाँ कतय पहुँचब।

### जुड़ल उदाहरण
Convex function एकटा टेबुल पर राखल एकल चिकना मिक्सिंग बाउल जकाँ अछि — भीतर कतहु marble छोड़ी, ई हरदम एकहि केंद्र बिंदु दिस लुढ़कि जाएत। Non-convex function एकटा अंडाक ट्रे (egg carton) जकाँ अछि — marble छोड़ी त ई *जे भी* dimple क नजदीक अछि ओहिमे बैसि जाएत, जरूरी नहि जे पूरा ट्रेक सबसँ गहिराह वला हो।

### ML मे ई कतए भेटत
- **Linear regression आ logistic regression** मे convex loss surface होइत अछि — gradient descent गारंटीसँ सबसँ नीक समाधान खोजि लेत, कतहुसँ शुरू करी।
- **Neural networks मे बहुत non-convex loss surface** होइत अछि — लाखो dimples। यैह किएक random weight initialization, learning rate schedules, आ momentum जकाँ चीज एतेक मायने रखैत अछि: अहाँ नीक dimple मे उतरबाक कोशिश करैत छी, जरूरी नहि जे गणितीय रूपसँ सबसँ नीक हो (आ व्यवहारमे, "पर्याप्त नीक" dimple भी बहुत नीकसँ काज करैत अछि)।

### अभ्यास
1. **हाथसँ:** कागज पर `f(x) = x²` (convex) आ `f(x) = x⁴ - 4x²` (non-convex — एहिमे दूटा गड्ढा अछि) केँ `x` -3 सँ 3 धरि लेल sketch करू। हर एकमे अहाँके जतय minima लागए ओतय निशान लगाउ।
2. **NumPy — दुनूकेँ देखू:**
   ```python
   import numpy as np
   import matplotlib.pyplot as plt

   x = np.linspace(-3, 3, 200)
   convex = x**2
   non_convex = x**4 - 4*x**2

   fig, axs = plt.subplots(1, 2, figsize=(10, 4))
   axs[0].plot(x, convex); axs[0].set_title("Convex: one minimum")
   axs[1].plot(x, non_convex); axs[1].set_title("Non-convex: two minima")
   plt.show()
   ```
3. **सोचू:** Non-convex plot मे, जँ gradient descent `x = 2.5` सँ शुरू होइत अछि, त ई शायद कोन गड्ढामे खसत? आ जँ `x = -0.5` सँ शुरू होइत अछि? अपन intuition जाँचबाक लेल नीचाँ Section 3 क gradient descent code दुनू शुरुआती बिंदु सँ चला क देखू।

## 2. लोकल मिनिमा, ग्लोबल मिनिमा, आ सैडल पॉइंट

### विचार
- **Global minimum**: पूरा function मे सबसँ नीचाँक एकल बिंदु।
- **Local minimum**: एहन बिंदु जे अपन तुरंतक पड़ोसीसँ नीचाँ अछि, मुदा जरूरी नहि जे कुल मिला क सबसँ नीचाँक बिंदु हो — अंडाक ट्रेमे एकटा dimple जकाँ जे सबसँ गहिराह नहि अछि।
- **Saddle point**: एहन बिंदु जतय surface समतल अछि (gradient ≈ 0) मुदा ई असलमे minimum नहि अछि — ई एक दिशामे ऊपर मुड़ैत अछि आ दोसर दिशामे नीचाँ, घोड़ाक saddle (जीन) जकाँ। एहिठाम gradient descent बहुत धीमा भऽ सकैत अछि, "समतल" केँ "पहुँचि गेलहुँ" बुझि क गलती कऽ सकैत अछि।

### जुड़ल उदाहरण
कल्पना करू अहाँ कोहरामे पहाड़ी शृंखला सँ नीचाँ उतरि रहल छी, सबसँ नीचाँक घाटी खोजैत। अहाँ एकटा एहन घाटीमे जा सकैत छी जे तर लागत (एकटा local minimum) — अहाँक तुरंतक चारूकात समतल जमीन — बिना जानने जे दू पहाड़ी पार एकटा आर बहुत गहिराह घाटी अछि (global minimum) जकरा कोहराक कारणे अहाँ देखि नहि सकैत छी। Saddle point एहन थिक जेना एकटा पहाड़ी दर्रा (mountain pass) पर ठाढ़ भेल — जकर दिशामे अहाँ चलि रहल छी ओ समतल अछि, मुदा अहाँक बाएँ आ दायाँ ई तेजीसँ खसैत अछि — जँ अहाँ केवल अपन पएरक ठीक नीचाँ जाँचैत छी त "हम पहुँचि गेलहुँ" बुझि लेब आसान अछि।

### ML मे ई कतए भेटत
- एकटा न्यूरल नेटवर्क train करब लगभग कहियो *global* minimum खोजबाक गारंटी नहि दैत अछि — practitioner "पर्याप्त नीक" local minimum खोजैत छथि, आ high-dimensional deep learning मे, research सुझाबैत अछि जे व्यवहारमे भेटल अधिकांश local minima असलमे बहुत नीक होइत अछि।
- Saddle points high dimensions मे खराब local minima सँ बेसी व्यावहारिक समस्या थिक — बहुत रास optimizer डिजाइन (momentum, Adam) विशेष रूपसँ समतल/saddle क्षेत्रसँ आगाँ बढ़बाक लेल अछि, फँसबासँ बचबाक लेल।

### अभ्यास
1. **हाथसँ (concept):** Section 1 क `f(x) = x⁴ - 4x²` लेल, `f'(x) = 0` कतय अछि से निकालू (derivative लिय, शून्यक बराबर राखू, x निकालू)। अहाँके 3 गोट बिंदु भेटत — कोन minima थिक, आ कोन न त min न max?
2. **NumPy — समतल बिंदु numerically खोजू:**
   ```python
   import numpy as np

   def f(x):
       return x**4 - 4*x**2

   def fprime(x):
       return 4*x**3 - 8*x

   for x in np.linspace(-3, 3, 13):
       if abs(fprime(x)) < 0.5:
           print(f"Near-flat region around x={x:.2f}, f(x)={f(x):.2f}")
   ```
3. **सोचू:** एकटा "समतल" क्षेत्र (जतय gradient शून्यक नजदीक अछि) साधारण gradient descent केँ बहुत समय किएक लऽ सकैत अछि निकलबामे, भलेहि ई असलमे minimum नहि हो? (संकेत: सोचू gradient खुद बहुत छोट रहला पर gradient descent कतेक बड़का कदम लैत अछि।)

## 3. लर्निंग रेट (Learning Rate)

### विचार
Learning rate ओ आकार थिक जे gradient descent "नीचाँ" जाइत काल हर कदममे उठबैत अछि। बहुत छोट भेला पर training हमेशा रेंगैत रहत। बहुत बड़ भेला पर अहाँ minimum के पार कऽ जाएब — शायद जोरसँ उछलैत रही या बिलकुल diverge भऽ जाई।

### जुड़ल उदाहरण
कल्पना करू अहाँ गाड़ीके एकटा सँकरा जगहमे पार्क करबाक लेल gas पंप कऽ रहल छी। Gas पर छोट-छोट थपकी (छोट learning rate) अहाँके कतहु त पहुँचाओत, मुदा बहुत धीरे-धीरे। पूरा गाड़ी दऽ देब (बड़ learning rate) अहाँके जगह पूरा तरहेँ पार करा सकैत अछि, फेर दोसर दिशामे बेसी सुधार करि देत, फेर आर, कहियो ठीकसँ नहि टिकत।

### ML मे ई कतए भेटत
- Learning rate पूरा deep learning मे सबसँ महत्वपूर्ण hyperparameters मे सँ एक थिक। एकरा गलत करी त एकदम नीक मॉडल architecture सेहो train होएबामे विफल भऽ जाएत।
- **Learning rate schedules** (शुरूमे बड़, समय संग छोट होइत) मानक अभ्यास थिक — जखन minimum सँ दूर छी तखन बड़, आत्मविश्वासी कदम, फेर जखन नजदीक पहुँची तखन छोट, सावधान कदम, ताकि overshoot नहि हो।

### अभ्यास
1. **NumPy — learning rate क असर सीधा महसूस करू:**
   ```python
   import numpy as np

   def f(x):
       return x**2

   def fprime(x):
       return 2*x

   def run_gd(lr, steps=15, start=5.0):
       x = start
       history = [x]
       for _ in range(steps):
           x = x - lr * fprime(x)
           history.append(x)
       return history

   for lr in [0.01, 0.1, 0.9, 1.01]:
       print(f"\nlearning rate = {lr}")
       print([round(v, 3) for v in run_gd(lr)])
   ```
2. **सोचू:** ऊपरक कोन learning rate सहजतासँ converge करैत अछि? कोन रेंगैत रहैत अछि? कोन हिलैत-डुलैत या फाटि जाइत अछि? कोड चलेबासँ पहिने पैटर्न अनुमान लगेबाक कोशिश करू, फेर जाँचू।
3. **Plot करू:** हर learning rate लेल, `x` value केँ step number क विरुद्ध plot करू। अहाँके एकटा सहज converge होइत curve, एकटा बहुत धीमे रेंगैत curve, आ एकटा जोरसँ हिलैत (या फाटैत) curve देखाएत।

## 4. स्टोकास्टिक ग्रेडिएंट डिसेंट (SGD)

### विचार
"Vanilla" (batch) gradient descent एकटा कदम बढ़ेबासँ पहिने अहाँक *पूरा* dataset उपयोग कऽ gradient निकालैत अछि — सटीक, मुदा लाखो data points होला पर धीमा। **Stochastic Gradient Descent** एकर बदला हर कदममे केवल *एक* (या एकटा छोट batch) randomly चुनल data points उपयोग कऽ gradient क अनुमान लगबैत अछि। ई एकटा शोरगुल वला, तेज तरीका थिक लगभग एकहि दिशा पाबैक लेल, बहुत बेसी (सस्ता) कदम उठा क कम (महग) कदमक बदला।

### जुड़ल उदाहरण
कल्पना करू अहाँके अपन शहरक सबटा लोकक औसत ऊँचाइ जानब अछि, दरवाजा कतेक ऊँच बनाबय से तय करबाक लेल। Batch gradient descent एहन थिक जेना कोनो निर्णय लेबासँ पहिने सचमुच हर एक व्यक्तिके माप लेब — सटीक मुदा दर्दनाक रूपसँ धीमा। SGD एहन थिक जेना एक-एक बेर एकटा random राहगीरसँ पूछब, हर व्यक्तिक बाद थोड़ेक अपन अनुमान बदलब — शोरगुल आ उछल-कूद वला, मुदा अहाँ तुरंत सुधार शुरू करि सकैत छी आ फेर भी लगभग सही उत्तर पर पहुँचि जाएब, कुल मिला क बहुत तेज।

### ML मे ई कतए भेटत
- लगभग सबटा deep learning training SGD या ओकर variant (mini-batches सहित — एकटा नमूना आ पूरा dataset क बीचक बीचोंबीच) उपयोग करैत अछि कियाक dataset हर कदम पर पूरा-batch gradient निकालबाक लेल बहुत बड़ अछि।
- SGD क "शोर" केवल नुकसान नहि थिक — ई असलमे optimizer केँ shallow local minima आ saddle points सँ बाहर निकलबामे मदद करि सकैत अछि, कियाक हर कदम केवल एकटा अनुमान थिक आ ई surface केँ बिलकुल सही ढंगसँ नहि पालैत अछि।

### अभ्यास
1. **NumPy — linear regression पर batch GD बनाम SGD compare करू:**
   ```python
   import numpy as np

   np.random.seed(0)
   X = np.linspace(0, 10, 200)
   y = 2 * X + 1 + np.random.normal(0, 1, size=X.shape)

   # --- Batch Gradient Descent ---
   w, b = 0.0, 0.0
   lr = 0.01
   for epoch in range(50):
       y_pred = w * X + b
       error = y_pred - y
       dw = (2/len(X)) * np.sum(error * X)
       db = (2/len(X)) * np.sum(error)
       w -= lr * dw
       b -= lr * db
   print(f"Batch GD result: w={w:.3f}, b={b:.3f}")

   # --- Stochastic Gradient Descent (1 sample per step) ---
   w, b = 0.0, 0.0
   lr = 0.01
   for epoch in range(50):
       indices = np.random.permutation(len(X))
       for i in indices:
           xi, yi = X[i], y[i]
           y_pred = w * xi + b
           error = y_pred - yi
           dw = 2 * error * xi
           db = 2 * error
           w -= lr * dw
           b -= lr * db
   print(f"SGD result: w={w:.3f}, b={b:.3f}")
   ```
2. **सोचू:** दुनूके `w≈2, b≈1` क नजदीक पहुँचक चाही। कोन तरीका मे व्यक्तिगत weight-update कदम बेसी उठाओल गेल? 10 करोड़ rows वाला dataset लेल कोन तरीका बेसी नीकसँ scale करत, आ किएक?
3. **अंतर plot करू:** दुनू तरीका लेल हर *epoch* क बाद loss value track आ plot करू। Batch GD क loss curve सहज रहत; SGD क शोरगुल वला रहत मुदा एकहि दिशा दिस झुकत।

## 5. मोमेंटम (Momentum)

### विचार
Momentum gradient descent मे "याददाश्त" जोड़ैत अछि: केवल वर्तमान gradient देखबाक बदला, ई हालक कदममे चलैत रहल दिशा पर भी विचार करैत अछि, आ ओहि गतिक किछु हिस्सा राखि लैत अछि। ई शोरगुल भरल zig-zag केँ सहज बनाबैत अछि आ समतल क्षेत्र आ shallow local minima/saddle points सँ आगाँ बढ़बामे मदद करैत अछि।

### जुड़ल उदाहरण
साधारण gradient descent एहन थिक जेना नीचाँ चलब, पूरा तरहेँ रुकब, ढलान जाँचब, एक कदम बढ़ब, फेर पूरा तरहेँ रुकब, फेर जाँचब — सावधान मुदा धीमा, आ छोट उभारसँ आसानीसँ मूर्ख बनि जाइत। Momentum एहन थिक जेना गेंद केँ नीचाँ *लुढ़काएब*: ई ओहि दिशामे रफ्तार बना लैत अछि जाहिदिश ई लगातार बढ़ि रहल अछि, त छोट उभार आ समतल हिस्सा एकरा रोकि नहि पबैत — ई जमा भेल momentum सँ ओहिमेसँ निकलि जाइत अछि, ठीक जेना असल गेंद करत।

### ML मे ई कतए भेटत
- लगभग हर आधुनिक optimizer (Momentum SGD, Adam, RMSprop) एहि विचार पर बनल अछि। ई vanilla gradient descent मे कएल जा सकैत सबसँ सरल, सबसँ प्रभावशाली बदलाव मे सँ एक थिक।
- ई loss surface क सँकरा, मुड़ल घाटी लेल खास रूपसँ उपयोगी अछि, जतय vanilla gradient descent घाटीक दीवारक बीच zig-zag करैत रहैत अछि, ओकर तर सहजतासँ नीचाँ जेबाक बदला।

### अभ्यास
1. **NumPy — Momentum from scratch बनाउ आ vanilla GD सँ compare करू:**
   ```python
   import numpy as np

   # A "narrow valley" loss surface: steep in y, shallow in x
   def f(x, y):
       return 0.1 * x**2 + 5 * y**2

   def grad(x, y):
       return np.array([0.2*x, 10*y])

   # --- Vanilla Gradient Descent ---
   point = np.array([-8.0, 3.0])
   lr = 0.08
   path_vanilla = [point.copy()]
   for _ in range(30):
       point = point - lr * grad(point[0], point[1])
       path_vanilla.append(point.copy())

   # --- Gradient Descent with Momentum ---
   point = np.array([-8.0, 3.0])
   velocity = np.array([0.0, 0.0])
   beta = 0.9  # how much past velocity to keep
   path_momentum = [point.copy()]
   for _ in range(30):
       g = grad(point[0], point[1])
       velocity = beta * velocity - lr * g
       point = point + velocity
       path_momentum.append(point.copy())

   print("Vanilla GD final point:", path_vanilla[-1])
   print("Momentum final point:", path_momentum[-1])
   ```
2. **दुनू path plot करू:** `path_vanilla` आ `path_momentum` केँ NumPy arrays मे बदलू आ हुनकर `x, y` trajectories केँ एकहि graph पर plot करू (शायद तर `f` क contour plot सहित, `plt.contour` उपयोग कऽ)। देखू कोना vanilla GD सँकरा घाटीमे zig-zag करैत अछि जखन कि momentum path केँ सहज बनाबैत अछि।
3. **प्रयोग करू:** `beta = 0.0` (कोनो momentum नहि, vanilla क बरोबर होबाक चाही), `beta = 0.5`, आ `beta = 0.99` कोशिश करू। Path कोना बदलैत अछि? कतेक momentum पर overshoot शुरू होइत अछि?

## 6. Adam Optimizer (Concept रूपमे परिचय)

### विचार
Adam ("Adaptive Moment Estimation") दूटा विचार मिलबैत अछि: (1) momentum — अहाँ जकर दिशामे बढ़ि रहल छी से मोन राखब — आ (2) **adaptive learning rates** — जे parameters मे ऐतिहासिक रूपसँ छोट/लगातार gradients रहल अछि हुनकर लेल automatically बड़ कदम उठाएब, आ जे parameters मे बड़ या अनियमित gradients रहल अछि हुनकर लेल छोट, सावधान कदम। हर parameter केँ असलमे अपन personalized learning rate भेटैत अछि जे समयक संग बदलैत अछि।

### जुड़ल उदाहरण
कल्पना करू अहाँ एकटा soundboard पर कैइयो अलग-अलग dial सही मिश्रणक लेल adjust कऽ रहल छी। किछु dial (जेना "master volume") केँ छोट सावधान झटका चाही — अहाँ हरदम सही value क नजदीक रहैत छी आ overshoot नहि करक चाहैत छी। दोसर dial (जेना अनछुआल EQ knob) केँ बड़, आत्मविश्वासी झटका चाही कियाक अहाँ ओहिठामसँ बहुत दूर शुरू करैत छी, आ पहिनुक adjustment ओतय छोट आ predictable रहल अछि। Adam एकटा सहायक जकाँ अछि जे देखैत अछि अहाँ हर dial कोना adjust करैत आएल छी आ automatically तय करैत अछि "एहि dial केँ बड़ मोड़ चाही, ओहिकेँ छोट झटका" — बिना अहाँ dial-दर-dial स्पष्ट रूपसँ बतेने।

### ML मे ई कतए भेटत
- Adam आइ अधिकांश deep learning मॉडल train करबाक लेल default, go-to optimizer थिक (अहाँ एकरा Phase 5 मे सीधे implement आ tune करब)। ई लोकप्रिय अछि कियाक ई कम tuning सँ व्यापक समस्यामे ठीकसँ काज करैत अछि, momentum आ per-parameter adaptive step sizes दुनूक फायदा मिलाकऽ।
- अखन अहाँके Adam क पूरा update equations हाथसँ निकालबाक जरूरत नहि — एहि चरणमे मुख्य बात ई बुझब अछि जे ई *किएक* अछि: momentum (समतल जगहसँ आगाँ बढ़ब/सहज करब) + adaptive rates (हर parameter केँ एकहि तरहसँ नहि मानब)।

### अभ्यास
1. **Concept:** Section 5 क "सँकरा घाटी" उदाहरणमे (`f(x, y) = 0.1x² + 5y²`), `x` दिशा shallow अछि (बड़ कदम चाही) आ `y` दिशा steep अछि (छोट, सावधान कदम चाही)। अपन शब्दमे बताउ किएक `x` आ `y` दुनू लेल *एकहि, साझा* learning rate एहि surface लेल बुनियादी रूपसँ बेमेल अछि — आ किएक per-parameter adaptive rates (Adam क मूल विचार) मददगार होएत।
2. **Python — असल Adam optimizer उपयोग कऽ convergence speed compare करू:**
   ```python
   # This uses PyTorch just to *observe* Adam's behavior — full PyTorch mechanics come in Phase 5.
   # If PyTorch isn't installed: pip install torch --break-system-packages
   import torch

   def loss_fn(params):
       x, y = params[0], params[1]
       return 0.1 * x**2 + 5 * y**2

   params = torch.tensor([-8.0, 3.0], requires_grad=True)
   optimizer = torch.optim.Adam([params], lr=0.3)

   for step in range(30):
       optimizer.zero_grad()
       loss = loss_fn(params)
       loss.backward()
       optimizer.step()

   print("Adam final point:", params.detach().numpy())
   ```
   Section 5 क अहाँक vanilla GD आ Momentum runs सँ compare करू जे Adam केँ एहन छोट बिंदु तक पहुँचबामे कतेक कम कदम लागल।
3. **सोचू:** Adam तेजीसँ converge करैत अछि आ vanilla SGD सँ कम learning-rate tuning चाही — त कैइयो state-of-the-art परिणाम अखनो कहियो-कहियो Adam क बदला plain SGD with momentum उपयोग करबाक रिपोर्ट किएक करैत अछि? (ई एकटा खुला research प्रश्न थिक — "Adam vs SGD generalization" पर एकटा quick search अहाँके चलैत बहसक स्वाद देत; एहि चरणमे कोनो एकहि सही उत्तरक अपेक्षा नहि अछि।)
